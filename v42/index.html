TAMPER-EVIDENT MEMORY LEDGER · SHA-256 HASH CHAIN

Editing an entry breaks the chain at that block. An attacker who edits and recomputes every later hash still fails, because the final hash was anchored separately when the entry was written.

WHY THE SEPARATION MATTERS

Mizan never reads the rationale. The agent's explanation is the easiest place to hide a manipulation, so the mediator decides only from the structured request and the policy.

EVE can only restrict. A critic that could approve things would just become another target. Its findings can add a denial, never remove one.

Approval is bound to the request. A human approves one exact request and gets a token for it. Claiming approval in text, or changing a field afterwards, does not work.

Memory is evidence. Writes are screened for injected instructions and chained by hash, so poisoning the agent's memory is both harder and detectable.

This page is an illustration: the rules are deterministic and run in your browser. The research prototype goes further and keeps an explicit no-go boundary for consequential autonomous use.
